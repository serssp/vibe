# Testing strategy

Status: completed MVP accepted by the user. These checks guide regression verification for future changes. Automated checks never use a valid OpenAI key or make real OpenAI requests.

## Required local and CI checks

Run `npm run check`, then `npm run test:browser`. The first command runs application and pure-Domain typechecks, lint, formatting, dependency checks, Vitest, and the production build. GitHub Actions runs those checks plus browser tests before deploying. `npm ci` installs the development-only `fake-indexeddb` test dependency from the lockfile.

Repository integration tests use a fresh `fake-indexeddb` factory per fixture, with no global browser dependency. The application ships migrations 1–3. Regression tests upgrade actual v1 and legacy v2 records to v3, preserve existing preferences and facts, and roll back failed v2-to-v3 changes. Additional failing/synthetic migrations in fixtures verify runner rollback without shipping hypothetical application migrations.

`tests/browser-check.mjs` runs against production preview on port 4173. `tests/storage-browser-check.mjs` serves source modules and synthetic fixtures through Vite on port 4174, then exercises native Chromium IndexedDB. Synthetic data and test modules are absent from the production build. The second suite validates browser transaction behavior, while the first verifies the actual production UI. `tests/learning-browser-check.mjs` separately runs generation/vocabulary/grammar against production preview, using mocked Responses payloads and Chromium native touch input through CDP. It verifies that scroll and cancelled pointers cannot produce synthetic-click analysis. All scripts use isolated browser contexts and shut down their servers. Test screenshots in this environment are saved under `/tmp/vibe-stage3-5`; they contain only mock records.

## Reading, backup and stabilization coverage

`tests/reading-cycle.test.ts` covers reliable canonical occurrences, absent and ambiguous words, canceled marks, first-session protection, later marks, candidate selection, atomic/idempotent completion, concurrent connections, position/completion races, pending-intent recovery, explicit rereading and local per-word evidence. A completed session rejects late undo.

`tests/backups.test.ts` covers all-store round trips, empty backups, version/shape/identity/reference errors, secret-field exclusion, revalidation after preview mutation and replacement rollback after a synthetic capacity failure. The storage fixture retains 2000 documents and sessions without truncation.

`tests/daily-browser-check.mjs` runs production preview on port 4175. It closes/reopens a tab to verify saved position and marks, completes first/new repetitions, views completed history, explicitly rereads, downloads a real JSON file, rejects/cancels/accepts imports, preserves the separate key, blocks unresolved completion, displays word facts, restores 502 documents and checks 20/40-row pagination. It records elapsed time for that history scenario and checks 150% mobile scaling. `VIBE_SITE=https://serssp.github.io/vibe/` runs the same mocked workflow against the deployed site without starting a local server. The browser context is isolated from user data. Screenshots use synthetic data under `/tmp/vibe-stage6-8`.

## Verification limits and manual checks

Chromium at 390×844 is an automated mobile viewport check, not a real Android Chrome verification. Tests use synthetic learning records and mocked AI results. They verify browser gestures and application contracts, but do not assess the quality of real generated German, model sense matching, CEFR accuracy, or real-device touch behavior. Automated reading-cycle tests verify completion facts and state transitions.

For future changes, report Android Chrome checks separately from automated Chromium. Real OpenAI content quality and device gestures require manual regression checks. A successful local check does not prove deployed GitHub Actions or a published version; report each separately. User acceptance of the completed MVP does not imply that the agent performed real-device or real-model verification.

Real OpenAI requests require an explicit user action. `npm run check:cors` is a separate real-network diagnostic with an intentionally invalid key; it is excluded from required checks and CI. Do not log keys or copy them into fixtures, screenshots, reports, exports, or builds.

## Manual generation, vocabulary and grammar regression

When checking changes to generation or reader interactions, use a real Android Chrome device. Save a valid key/model locally, generate each intended level/duration, and assess German coherence, length and CEFR. Refresh and confirm the same text returns without another request. Tap inflected words and nouns, verify the contextual Russian meaning and article/gender, undo an accidental tap, and check vocabulary after refresh. Compare distinct meanings of the same spelling and a separable verb or fixed expression.

Hold a word for about 500 ms: the whole sentence should be highlighted with a Russian explanation and no vocabulary mark. Check short taps, scrolling, movement, cancellation and the system context menu; use the sentence-analysis button as an alternative. Retry after disabling/restoring connectivity and confirm failed word marks remain available. Do not put the key into feedback. Record real requests, phone/browser version, and device observations separately from mocked tests.

## Manual reading, history and backup regression

On real Android Chrome, generate a text, mark a word, scroll, switch apps, close/reopen the tab and verify recovery. Complete reading: the new word must remain Unknown. Generate again and check a reliably included untapped word becomes Learned; a tapped word stays Unknown and an absent word is unchanged. Press completion again or refresh: counters must not increase twice. Review local word facts.

Open an older unfinished text and refresh: that selected reading and position should return. View a completed text: learning facts must remain unchanged. Start a new session explicitly and confirm a new mark changes Learned back to Unknown. Export, change local learning data, choose the backup, cancel once, then restore after explicit confirmation. Verify texts, sessions, pending marks and cached explanations; key replacement/deletion still work independently. Test malformed and unsupported JSON files. Keep a backup before testing updates with real data.

Exercise taps, 500 ms holds, scrolling, canceled touches, enlarged system fonts, card scrolling and one-handed access to completion and history. Test network loss during each explicit AI action and cached reading while already open. Record phone model, Android/Chrome versions, real model name and observations without including credentials. Abrupt OS process termination can lose movement since the last committed debounce save; pagehide is best effort. iOS Safari compatibility is not certified by the Chromium suite.

## Leselampe design regression

`tests/reader-preferences.test.ts` checks malformed/unsupported preference recovery, unavailable storage, bounded settings, original connection-key compatibility and rejection of invalid writes. `tests/browser-navigation.mjs` adapts the existing workflows to Library, Reader, Vocabulary and Settings without changing learning assertions.

`tests/design-browser-check.mjs` uses production preview on port 4176 with mocked Responses transport. It verifies panel Back/Escape/downward dismissal, compact and expanded selected-word geometry, accessible grammar, cancellation during a delayed word response, stale-result isolation, durable Pending recovery, cached mark/undo, typography and sentence-position restoration, stable sentence IDs, library scroll restoration, local filters, deep links and generation Back. All screens and generation/word panels are checked for horizontal overflow at 320, 360, 390 and 430 CSS pixels with 100% and 200% root text. This simulates system text scaling; real browser pinch zoom and Android toolbar behavior require device verification.

The compact word fixture must occupy less than 35% of the 390×844 viewport, show grammatical metadata immediately and keep the full sentence/form explanation under More. The learning suite checks that distinct inflected forms remain visible, noun gender is available without expansion, separable expressions remain available in details and opening details does not request AI.

Dictionary-form checks use word prompt v2 mock responses. Structured transport tests require the new nullable fields and reject empty/misclassified forms and nested unknown fields. Backup tests round-trip both legacy and enriched cards without a migration; a cache-version test preserves v1 translations and reuses v2 only after an explicit lookup. Browser checks show noun articles and full plural immediately, irregular/separable verb Präteritum and Perfekt with the auxiliary, and no principal-parts row for regular verbs. Noun and irregular-verb sheets are checked at all four phone widths and 200% root text. Real model accuracy for plural forms, irregular classification and auxiliary choice still requires an explicit real-device/model check.

Screenshots are generated under `/tmp/vibe-leselampe` by default; `VIBE_SCREENSHOTS` overrides the directory. Selected mobile captures are retained in `docs/screenshots/leselampe`. `VIBE_SITE=https://serssp.github.io/vibe/` can run this suite against the published site in an isolated context. Required `npm run test:browser` includes this suite, so deployment runs the same design regressions.

Word-sheet gesture checks use native Chromium touch events through CDP, plus mouse dragging and keyboard/handle alternatives. They cover body/handle upward expansion, downward dismissal while loading, short/horizontal/cancelled/secondary-touch gestures, click suppression after dragging, native scrolling of a long expanded explanation and absence of duplicate More/Close buttons. Expansion and dismissal preserve mark counts and issue no additional AI requests. Existing learning/daily workflows use Escape and the accessible handle in the shared navigation helpers, retaining cache/undo/recovery assertions. Real Android Chrome toolbar, touch and accessibility behavior still requires device verification.

Manual design acceptance still requires real Android Chrome: browser Back, taps/holds, downward dismissal, reader and card scrolling, software keyboard, browser toolbar resizing, 200% zoom/system scaling, refresh and recovery. Real model quality and device checks must be reported separately from automated mock transport checks.
